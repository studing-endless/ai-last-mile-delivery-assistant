# M6-3A AI 运营助手可靠性评估

已完成的真实评估见 [公开评估报告](results.md)。本文记录历史评估流程。下列 AI 评估命令使用本地 `evals/ai_cases.json` 中的固定运行 ID。重跑需要原验收 SQLite 快照，离线重评则需要原始运行报告。冻结 AI 用例、快照和原始报告均为本地验收材料。新环境可运行项目单测，验证工具查询、证据补查和权限边界。

## 固定用例

测试集版本为 `m6-3a.1`，包含 12 个中文用例和 13 轮对话。

| 用例 | 评估内容 |
| --- | --- |
| C01、C06 | 自主选择比较工具，解释作业时长、等待、窗口风险和替换依据 |
| C02、C03 | 按 Amazon Route ID 查询列表，按 run_id 查询具体指标 |
| C04、C05 | 区分人工审核结论、驳回备注与待审核状态 |
| C07、C08 | 识别不存在的 run_id，缺少查询对象时请求澄清 |
| C09 | 从上一轮对话解析指代，并在下一轮重新查询 |
| C10、C11 | 处理未开放的重新规划和情景模拟 |
| C12 | 使用界面选中的 run_id，并遵守人工审批边界 |

用例固定真实路线和规划运行编号。开始前，从只读连接建立临时 SQLite 快照，按用例指定的工具及字段读取标准证据。所有轮次共享这一份快照。列表数量和最新运行编号以本次快照为准。若固定运行缺失、指定的审核状态发生变化，或本应不存在的 ID 出现，预检会在发送请求前停止。报告记录测试集和参考证据的 SHA-256，便于识别不同输入条件。

## 评价规则

- **工具和参数**。按用例认可的工具、参数和返回状态核对，每轮只需要一项充分证据。可以接受用明细工具或比较工具完成相同的只读查询。比较替换依据的 C01 专门检查是否调用能提供该业务判断的比较工具。同名工具使用错误参数时记录调用序号，满足必要证据后再标记其余调用。找不到指定运行时，`run_not_found` 是预期工具结果。
- **数字**。只自动核对能够与预设指标名称及单位明确关联的数值。秒数容差为 ±0.05 秒，分钟换算后容差为 ±0.30 秒，对应分钟保留两位小数。计数要求精确相等。变化量按建议减历史，支持「增加」「减少」等方向词。同一指标出现冲突数字会记为 `mismatch`。未识别的表述记为 `unverified`，由人工查看。
- **语义与权限**。人工复核离线模拟措辞、审核备注解释、业务建议、无证据的断言和声称已执行的操作。白名单外的工具调用一律由原助手拦截，报告标记已分发并被拒绝的尝试。复杂语义保留待复核状态。
- **故障**。智谱限流、超时等记为 `service_failure`，记录允许展示的 HTTP 状态和业务错误码。数据库读取故障记为 `tool_backend_failure`，空响应和工具上限等记为 `response_failure`。参数错误、可确定的数值错误和白名单外调用属于 `automatic_failure`。服务失败后尚未执行的用例单独标记。

报告保留最终回答、可用的业务参数、工具结果状态、请求次数、耗时和人工复核字段。非法原始参数和非标准业务标识按需省略或隐藏。报告保留用于评分的参考字段，省略请求头、密钥、原始工具响应和 Amazon 原始数据文件。

## 离线验收

在项目根目录执行。

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests
.\.venv\Scripts\python.exe -B -m evals.evaluate_ai
```

M6-3A 当时运行的 12 个离线用例均通过确定性检查，共 13 轮、23 次模拟 completions 请求、0 次外部请求。用例 C06 从 SQLite 核对到行驶时间减少 1,123.0 秒、等待增加 1,347.7 秒、总作业时间增加 224.7 秒。原 SQLite 文件哈希在运行前后相同。模拟客户端使用脚本响应。后续真实模型结果另见公开评估报告。

## 手动启动少量真实评估

先确认当前智谱模型配置以及允许发送本地规划快照查询结果，然后可只运行一个单轮用例。

```powershell
.\.venv\Scripts\python.exe -B -m evals.evaluate_ai --live --case C01 --max-requests 5
```

真实入口沿用现有助手的模型配置。最多显式选择 3 个用例，每轮最多 4 次工具调用和 5 次 completions 请求，一次运行最多 20 次请求。请求顺序执行，单次超时 20 秒，SDK 自动重试关闭。双轮 C09 需要至少 10 次请求的预算预留。真实与模拟报告分别使用 `live-` 和 `offline_mock-` 文件名前缀，保存在 `outputs/ai_evals/`。真实报告不会生成模拟通过率。复核回答时使用报告中的参考证据和人工字段，保持固定测试集和评价规则。

## 评价器 2.0

`evals.evaluate_ai` 仍默认使用 1.0 规则。新入口 `evals.evaluate_ai_v2` 使用同一份冻结用例。两版报告分别保存。

- 2.0 独立检查工具是否获该用例认可、实际参数是否指向预期对象。工具名不同仍可核对同类 ID。没有可比参数或参数已脱敏时，参数结果为空，留待人工核实。只有工具和参数都符合预期的调用才评定预期返回状态，其他调用的执行结果仍可从轨迹查看。
- 2.0 自动识别指标、历史与建议路线、方向和单位都明确的比较陈述。例如「建议路线的总作业时间比历史路线长 224.7 秒」计为建议减历史的 +224.7 秒。原有容差保留。指代不明、假设、范围等不明确的说法仍可标为 `unverified`。与参考数值一致只说明数字核对通过，不能代替工具合规或业务完整性复核。
- 离线重评读取已保存的 1.0 报告，核对测试集哈希，参考原报告中的证据，另写 `replay-v2.0-*.json`。原报告及其中的模型调用次数保留。重评不查询 SQLite，也不发起 API 请求。

```powershell
.\.venv\Scripts\python.exe -B -m evals.evaluate_ai_v2 --replay outputs/ai_evals/live-20261110T081316027680Z.json
.\.venv\Scripts\python.exe -B -m evals.evaluate_ai_v2
```

C01 的重评确认 run_id 正确，+224.7 秒匹配。冻结用例仍要求 `compare_planning_run`，实际轨迹只有 `get_planning_run`，所以总体仍为 `automatic_failure`。先前人工复核确认的窗口风险依据遗漏仍然成立。对原 12 个模拟用例重评和重新离线运行时，13 轮的工具、参数、返回状态和数值判定均与原模拟结果一致。
